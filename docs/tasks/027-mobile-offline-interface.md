# 027 — Екрани Shopik і повний офлайн-сценарій

Статус: Заплановано. Пріоритет: P1. Залежності: [022](022-capacitor-mobile-shell.md), [024](024-mobile-local-repository.md), [026](026-mobile-sync-engine.md).
Батьківський план: [Android plan](../MOBILE_ANDROID_PLAN.md).

## Мета

Перенести поточний мобільний UX на локальний репозиторій та погоджену чергу зі збереженням бізнес-правил 019.

## Роботи

- Підключити спільні ProductList/OrderModal/OrderCard/CreateAction/TagFilter, витрати й налаштування через адаптери; замінити Next-specific navigation/image/font/runtime.
- Реалізувати offline create категорії й тегу, у тому числі тег усередині товарної форми. Нові локальні сутності відразу доступні у виборі та фільтрах.
- Підтримати create/edit/delete/complete товарів, batch до 500, керування дозволеними категоріями/тегами, actual-price correction та видалення неархівної покупки.
- Зберегти quantity, точні копійки, OR без дублів, останню категорію в scope, згорнуті акордеони, фільтри, план/факт/економію й незмінний архів.
- Виводити «збережено на пристрої», pending count, «синхронізується», needs-auth/conflict/rejected/retry. Остаточно підтверджені й локально попередні суми розрізняються.
- Відображати лише відомі витратні періоди; незавантажений місяць має окремий стан, а не нуль. Зміна теми одразу зберігається локально.
- Додати зрозумілий вибір конфліктної версії та стан залежних операцій. При rejected локальному записі залишити можливість зрозуміти причину й виправити дозволені поля.
- Перевірити keyboard resize, Android Back для меню/діалогів, safe area/edge-to-edge, touch, довгий тап, focus, reduced motion та всі шість тем.

## Критерії готовності

- Без мережі користувач створює категорію, тег і товар, редагує його, завершує та бачить попередню витрату; після cold start усе відновлюється.
- Помилка локального запису не називається успіхом. Невідправлені зміни видимі, навіть якщо форма вже закрита.
- Старі author-only/AND-правила для покупок не повернулися. Сервер і локальна модель дають однакові підтверджені підсумки.
- На вузьких екранах і з клавіатурою доступні всі кнопки та останні картки.

## Перевірки

Unit грошових/фільтрових правил; UI/integration онлайн і офлайн; реальний Android WebView на підтримуваному мінімумі й актуальній версії; 320/360/390 CSS px, landscape, збільшений текст, шість тем. Вебрегресія спільних компонентів. Звіт: `docs/testing/027-mobile-interface/`.
