# 001 — Google Login та особистий Workspace

## Статус — 29.10.2026

Етап прийнято. Lint, TypeScript, тести конфігурації, HTTP-тести, перевірка анонімного доступу до реального Supabase та production build через Webpack пройшли.
Користувач підтвердив проходження браузерного сценарію з оновленням сторінки, другою вкладкою, logout та повторним входом; для повного SQL-тесту повідомлено `set_config: "{}"` без помилки. Ізоляція та відсутність дублікатів прийняті на основі цього повідомлення, а не самостійного запуску SQL агентом. Оновлення простроченого токена окремо не тестувалося.

## Реалізація

- Клієнти Supabase для браузера та сервера, конфігурація через `.env.local`.
- `/login` з Google OAuth (PKCE), `/auth/callback` з обміном коду на cookie-сесію.
- `proxy.ts` для оновлення cookie-сесії; головна сторінка перевіряє підписані claims на сервері.
- Вихід через Server Action; успішний logout повертає на `/login`.
- RPC створення профілю та особистого Workspace без дублікатів.
- RLS та заборона прямого редагування членства.
- Назва Workspace й поточна роль показані над демонстраційним списком.

## Критерії приймання

- Без сесії `/` перенаправляє на `/login`.
- Google Login повертає до особистого Workspace з роллю `owner`.
- Оновлення сторінки й повторний вхід не створюють дублікатів.
- Два користувачі не бачать дані просторів один одного.
- Logout прибирає локальну сесію; повторний доступ потребує входу.
- Відхилення OAuth дає можливість повторити вхід.

Інструкція налаштування та ручної перевірки: `docs/SUPABASE.md`.
Автоматичний SQL-тест RLS: `supabase/tests/auth_workspaces.sql`.
Повний Google OAuth та SQL-тест потребують налаштованого зовнішнього Supabase.
