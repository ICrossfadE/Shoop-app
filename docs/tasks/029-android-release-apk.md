# 029 — Android-приймання, підписаний APK та ручне оновлення

Статус: Заплановано. Пріоритет: P1. Залежності: [027](027-mobile-offline-interface.md), [028](028-mobile-workspaces-lifecycle.md).
Батьківський план: [Android plan](../MOBILE_ANDROID_PLAN.md).

## Мета

Передати встановлюваний release APK із перевіреним офлайн-циклом, зрозумілою інструкцією та повторюваною збіркою.

## Роботи

- Виконати узгоджені frontend/shared/mobile lint, typecheck, unit/integration/build, SQL/RLS і регресії вебверсії. Зберегти звіт із фактичним середовищем.
- Пройти на фізичному Android: login → sync → airplane mode → нова категорія/тег/товар → edit/complete → force stop/reboot → online. У вебі/на другому пристрої перевірити рівно одну сутність кожного типу, правильну дату, план, факт і підсумки.
- Перевірити втрату відповіді після server commit, kill до local ack, дубль відправника, два редактори, tag-only conflict, дубль назви, rejected, expiry auth, eviction/rejoin, logout і switch із чергою.
- Перевірити збереження існуючих server-даних і локальної черги при переході схеми; протестувати оновлення попереднього APK поверх установленого тим самим підписом, без uninstall.
- Налаштувати release signing, application ID, versionCode/versionName, HTTPS та release permissions. Keystore/паролі не зберігати в Git, документації або APK. Використати захищене надання секретів під час виконання цієї задачі.
- Випустити підписаний release `.apk`, checksum SHA256, назву версії, дату, вимоги Android і інструкцію ручного встановлення/оновлення. Окремо пояснити, що uninstall/очищення даних може видалити ще не синхронізовані локальні дії.
- Документувати зберігання/резервування signing key й процес наступного підписаного оновлення. Debug APK не позначати як фінальний release.

## Критерії готовності

- Чисте встановлення й оновлення на підтримуваних Android перевірені; release не залежить від dev/Vercel server для старту.
- Є фактичний APK, перевірка підпису й контрольна сума; користувач може встановити його за інструкцією.
- Підтверджені коректність даних, конфлікти та відновлення; неперевірені моделі/версії прямо перелічені.
- Фонові гарантії та непідтверджена фізична стійкість не заявляються на підставі desktop-тестів.

## Артефакти

Звіт: `docs/testing/029-android-release/`. Release APK і checksum — у визначеній release-папці/сховищі артефактів без секретів. Публікація в Google Play, AAB і магазинні матеріали не є умовою цієї задачі.
