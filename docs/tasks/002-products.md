# 002 — Продукти у Supabase

## Реалізовано

- Демонстраційний JSON видалений без перенесення його записів у базу.
- Нові продукти зберігаються в `public.products` відповідного Workspace.
- Server Actions: створення, редагування, видалення, завершення та повернення в активні.
- Список читається на сервері; після успішної зміни `revalidatePath('/')` оновлює дані.
- Назва обов'язкова, опис необов'язковий, валюта UAH; ціна не може бути від'ємною, нечисловою чи мати понад два десяткові знаки.
- SHA256 ID, автор, початковий статус і часові позначки генеруються базою.
- RLS та column grants захищають дані й незмінні поля від прямих Data API запитів.
- Порожній список, завантаження, помилки, повторне завантаження, блокування повторної відправки форми.
- Native dialog підтримує клавіатурну навігацію та Escape; введені поля зберігаються після помилки.

## Застосування й перевірка

1. Міграція **тільки цього етапу**: `supabase/migrations/202610290002_products.sql`.
2. Повний SQL-тест: `supabase/tests/products.sql`. Тест відкочує тестові дані; перевіряє CRUD, грошові обмеження, SHA256 ID, захист автора/Workspace, ізоляцію двох користувачів та роботу учасника спільного простору.
3. `npm test`, `npm run lint`, `npm run typecheck`, `npm run build -- --webpack`, `npm run test:smoke`, `npm run test:supabase`.
4. У браузері створити продукт без опису за 12,50 грн; оновити сторінку; редагувати; завершити; повернути в активні; видалити; оновити сторінку знову. Перевірити помилку для від'ємної ціни та для 0,001.

Результати реального SQL-тесту та браузерного CRUD записуються окремо після виконання; сам факт наявності тестового файлу не означає проходження перевірки.

## Результати перевірки — 29.10.2026

- Локально пройшли 10 тестів (6 продуктів, 4 конфігурації), lint, TypeScript та production build через Webpack.
- `test:supabase` підтвердив наявність products і заборону анонімного читання; HTTP-тести авторизації пройшли після врахування streaming redirect зі станом завантаження Next.js.
- Користувач повідомив успішне застосування міграції («Success. No rows returned»).
- Для запуску повного `supabase/tests/products.sql` користувач надав рядок Workspace з роллю owner без повідомлення про помилку. За умови виконання всього файлу це означає проходження перевірок; SQL-тест самостійно агентом не запускався.
- Браузерний CRUD із чинною Google-сесією агентом окремо не перевірений.

## Межі

Категорії, теги, фільтри, витрати, запрошення та realtime-синхронізація не входять у цей етап. Для отримання змін іншої вкладки чи учасника є кнопка «Оновити список».
